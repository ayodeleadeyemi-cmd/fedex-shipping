# Edge Shipping — Dynamic U.S. Shipping Portal

Edge Shipping is a server-backed shipping website for domestic routes across all 50 U.S. states. It is **not intended to be opened as a standalone `index.html` file**: the Node.js server powers shipment tracking, administrator authentication, quote requests, saved records, package holds/returns, and branding uploads.

The refreshed home page follows a familiar national-carrier information architecture: compact global navigation with drop-down menus, a courier-photo hero, Rate & Transit Times / Track / Ship actions, a tracking ID form, a business-support banner, shipment-management shortcuts, service features and a complete footer. It uses original Edge Shipping branding, a generated hero photograph and original wording; it does not use another carrier's logo, artwork or proprietary copy.

## What's working

- Responsive customer views for Home, Track, Ship with us, Services, Hold & returns, and Support/FAQs. The header has functional Shipping, Tracking, Support and Account drop-down menus plus a search shortcut that opens tracking. Each customer/admin view has its own refresh-safe URL path, older `#page` links still work, and browser Back/Forward navigation works.
- Public tracking lookup by tracking ID, shipment overview and chronological event timeline.
- Administrator sign-in, shipment metrics, searchable shipment register, server-generated tracking IDs, and tracking event/status updates.
- Customer hold and return requests saved to the server; the administrator can approve or reject requests. Approved holds set the shipment to **Held at facility**; approved returns set it to **Returning to sender**.
- Server-calculated illustrative quote estimates, saved as requests in the administrator queue.
- An authenticated Admin → **Branding** panel to upload/replace a website logo (PNG, JPG or WebP up to 750 KB) or restore the default Edge Shipping logo. The selected logo is displayed in the site header, footer, admin sign-in page, preview, and browser tab. Logo configuration and uploaded image are retained on the server filesystem.
- State selectors and server-side validation for the 50 U.S. states and ZIP / ZIP+4 formats.
- Local JSON persistence in `data/store.json`, created automatically on first start.
- No third-party npm dependencies.

## Run on Windows

1. Install **Node.js 20 or newer** from <https://nodejs.org/> if it is not already installed.
2. Extract the ZIP to a normal folder on your computer.
3. Double-click `start-windows.bat` (or open a terminal in this folder and run `npm start`). Keep the terminal open while using the site.
4. The launcher opens <http://127.0.0.1:3000> automatically. If it does not, open that address manually.
5. Open **Admin** in the site navigation and sign in.

**Important:** Don't double-click `public/index.html` or upload only the `public` folder to a static hosting service. A static file preview cannot run the API or save records; the page now displays a notice if opened directly. Deploy the whole project to a Node.js-compatible host to retain dynamic features.

## Configure credentials for deployment

For a public deployment, use `.env.production.example` as a guide, create a private `.env` or configure environment variables in your hosting provider, and set your own credentials, for example:

```env
PORT=3000
NODE_ENV=production
ADMIN_EMAIL=operations@your-company.com
ADMIN_PASSWORD=replace-with-a-long-unique-password
```

Restart the server after changing these values. Environment variables from the hosting provider take precedence over `.env`. Production mode requires a configured `ADMIN_PASSWORD`. Use HTTPS on the public site; production cookies are marked Secure.

## Suggested workflow test

1. In Home or Track, look up the sample ID `EDG-US-DEMO001` (sample data only).
2. Sign into Admin with the local demo credentials.
3. Choose **Create shipment** and enter a U.S. origin/destination to receive a new `EDG-US-...` tracking ID generated by the server.
4. Under **Shipments**, choose **Manage** and submit a new location, status and event note. Track the new ID on the customer-facing site to see the update.
5. Submit a hold or return request using a valid tracking ID. Under **Requests**, approve/reject it and confirm the tracking page reflects an approved hold/return.
6. On **Ship with us**, submit a quote. The estimate and request reference come from the server and the request appears in Admin → Requests.
7. Under Admin → **Branding**, upload a PNG, JPEG/JPG or WebP logo no larger than 750 KB, save it, and check the header/footer. Use **Restore default** to switch back.
8. Run `npm run check` to validate JavaScript syntax and `npm test` to run the built-in API smoke tests. The tests cover page routes, admin authentication, shipment creation, tracking updates, quote requests, hold approval, branding upload/reset, and logout.

## Limitations before a real business launch

This is a dynamic working starter, not a carrier-certified logistics platform. It does **not** connect to live FedEx, UPS, USPS or other carrier networks, GPS/driver data, live address validation, actual postage/shipping labels, payment processing or email/SMS notifications. Tracking locations and status events are entered by Edge Shipping operations. Quote prices and transit windows are illustrative only and are not carrier rates or guaranteed delivery commitments.

Shipment/request data is saved to a local JSON file and sessions are stored in server memory. For a public multi-user launch, migrate the JSON store to a transactional database, use durable session storage, add CSRF/security monitoring, logging/backups and role management, validate real delivery addresses, and integrate authorized carrier APIs and notifications. Also add the verified company contact details, privacy notice, terms, and actual service/return policies before accepting real customer shipments.
